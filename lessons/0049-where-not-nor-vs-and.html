실제로 본 코드

AppraisalResponse 모델에는 응답 하나가 "목표 응답인지, 핵심성과 응답인지, 배지 응답인지"를 구분해서 걸러주는 스코프들이 있다. 그중 for_objectives(목표 응답만 걸러내는 스코프)의 수정 전 코드는 이랬다. 

# 수정 전 — app/models/appraisal_response.rb
scope :for_objectives,
      lambda {
        where(key_result_id: nil, badgepool_id: nil)
          .where(job_template_question_id: nil, ...)
          .where.not(section_id: nil, element_id: nil, objective_id: nil)
      }

딱 봐서는 "section_id도, element_id도, objective_id도 전부 NULL이 아니어야 포함"이라고 읽힌다 — 즉 세 필드가 전부 존재해야(AND) 목표 응답으로 걸러진다는 의도다. 그런데 실제 dev 데이터로 확인해보니 이 스코프가 목표 응답 3건이 아니라 94건을 반환했다. 순수 섹션 응답(section_id만 있고 나머지는 다 NULL인 행)까지 섞여서 나온 것이다.

왜 이렇게 됐나 — where.not은 조건 전체를 하나로 묶어서 부정한다

where(a: nil, b: nil)는 익숙한 그대로 a IS NULL AND b IS NULL이 된다. 그런데 where.not(a: nil, b: nil)은 "a 아니고 b 아니고"가 아니라, 괄호로 묶인 조건 전체를 부정한다. 

where.not(a: nil, b: nil)
  → SQL: NOT (a IS NULL AND b IS NULL)

드모르간의 법칙(De Morgan's law)에 따라 NOT (P AND Q)는 (NOT P) OR (NOT Q)와 같다. 그러니까 실제로 생성되는 조건은: 

NOT (a IS NULL AND b IS NULL)
  = (a IS NOT NULL) OR (b IS NOT NULL)   ← OR다! AND가 아니다

즉 "a, b 중 하나만 non-null이어도" 이 조건은 참이 된다. 원래 의도("전부 non-null이어야 함")와 정반대로, "하나라도 있으면 통과"하는 NOR(Not-OR을 뒤집으면 사실상 OR) 스타일 조건이 만들어진 것이다.

JS로 치면 !(a && b)가 !a || !b와 같다는 것과 정확히 같은 얘기다. "and 전체를 부정하면 or로 바뀐다"는 논리 법칙 자체는 프론트에서도 매일 쓰던 것인데, Rails의 where.not(a: x, b: y)라는 표현이 "AND 조건들을 각각 부정한다"처럼 읽혀서 착각하기 쉬웠다. 실제로는 .not({a: x, b: y}) 하나가 통째로 !(a == x && b == y)인 것과 같다.

왜 하필 이 버그가 그동안 안 터졌나 — no-op이 되는 조건

이 스코프 앞에는 where(key_result_id: nil, badgepool_id: nil) 같은 필터가 먼저 붙어 있었다. 그리고 대상 행은 거의 항상 section_id가 채워져 있다. 그러면 where.not(section_id: nil, element_id: nil, objective_id: nil)의 OR 조건 중 section_id IS NOT NULL이 사실상 항상 참이 되어 이 절 전체가 no-op(있으나 마나)이 되어버린다. 그래서 앞단 필터를 통과한 행이면 뒤의 "위변조 방지용" 조건 없이도 전부 통과했고, 겉으로 보기엔 "대충 맞는 결과"가 나와서 오랫동안 발견되지 않았다.

퀴즈 1 — 실제로 생성되는 SQL

Model.where.not(a: nil, b: nil)이 실제로 생성하는 조건은?

고치는 법 — 체인으로 분리하면 AND가 된다

"a도 b도 전부 non-null"을 표현하려면, where.not을 각각 별도로 호출해서 체이닝해야 한다. 각 호출은 독립된 WHERE 절이라 Rails가 자동으로 AND로 묶어준다. 

# 수정 후 — 세 번의 별도 where.not 호출 = AND로 묶임
scope :for_objectives,
      lambda {
        where(key_result_id: nil, badgepool_id: nil)
          .where(job_template_question_id: nil, ...)
          .where.not(section_id: nil)
          .where.not(element_id: nil)
          .where.not(objective_id: nil)
      }

이렇게 고치자 for_objectives가 실제로 목표 응답 3건만 반환하도록 바뀌었다 (기존 94건은 핵심성과·순수 섹션 응답이 섞여 들어온 것이었다). rubocop에는 이 정확한 패턴을 잡아주는 Rails/WhereNotWithMultipleConditions cop이 있다 — "다중 키로 where.not을 호출하면 의도와 다른 NOR이 될 수 있으니 체이닝하라"고 정확히 지적해준다.

퀴즈 2 — 올바른 수정

"a, b 둘 다 non-null이어야 포함"을 올바르게 표현한 코드는?

핵심 요약

표현 실제 SQL 의미
where(a: nil, b: nil) a IS NULL AND b IS NULL 둘 다 NULL이어야 포함 (직관적)
where.not(a: nil, b: nil) a IS NOT NULL OR b IS NOT NULL 하나만 non-null이어도 포함 (❌ 의도와 다름)
where.not(a: nil).where.not(b: nil) a IS NOT NULL AND b IS NOT NULL 둘 다 non-null이어야 포함 (✅ 체이닝하면 AND)

참고: Rails API — ActiveRecord::QueryMethods#where · RuboCop Rails — Rails/WhereNotWithMultipleConditions
